# Web app

TypeScript + React + Vite. The M2 shell has two views, both driven by the Rust
core compiled to WebAssembly; the page itself never decides a Go rule:

- **Enter moves:** click to play, pass and undo on a 19×19, 13×13 or 9×9 board
  under a chosen rule set and komi. Illegal moves (occupied point, suicide,
  ko, superko where the rules forbid it) are rejected with the core's error
  code, shown as localized text.
- **Open SGF:** choose a file; the core decodes it (including legacy encodings
  such as GB18030), shows the game information, asks the user to confirm the
  rules and komi, replays the main line and lets the user step through it
  (buttons, slider, arrow keys, Home and End). Parser, extraction and replay
  warnings are listed with localized text.

The interface is available in English and Simplified Chinese
(`src/i18n.ts`). There is no analysis yet and no server call.

## Layout

| Path | Contents |
| --- | --- |
| `src/core.ts` | Loads the WASM module and re-exports the generated bindings |
| `src/session/` | Plain TypeScript wrappers around core handles (`ManualSession`) and SGF calls; no React |
| `src/components/` | React components: SVG `Board`, `PositionStatus`, `ManualPlay`, `RecordReplay` |
| `src/i18n.ts` | Locale catalogs; core error and warning codes map to text here |
| `src/test/` | Vitest setup (loads the WASM module synchronously) and test helpers |
| `src/wasm/` | Generated by `npm run wasm`; not committed |

React state holds only plain snapshots returned by the core (positions, move
lists); the one long-lived core handle (`Game` in `ManualSession`) is freed
explicitly when a new game replaces it.

## Commands

`npm run wasm` builds `crates/weiqi-wasm` and writes the generated module to
`src/wasm/`. It needs the `wasm32-unknown-unknown` target (from
`rust-toolchain.toml`) and `wasm-bindgen-cli` 0.2.130 on `PATH`.

```bash
npm ci
npm run wasm
npm run dev
npm run lint && npm run typecheck && npm test && npm run build
```
