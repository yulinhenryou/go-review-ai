## Property tests

| Property | What it checks |
| --- | --- |
| `strict_play_keeps_invariants_and_undo_restores_every_position` | Random boards (1–7 × 1–7, sometimes 19×19), all 9 presets, up to 300 random moves in `Strict` mode. After each applied move: incremental `stones_hash` equals `zobrist::stones_hash` recomputed from the board; stones on board = stones placed − stones removed, per color; under positional or situational superko no placement repeats an earlier position, compared by cells rather than by hash. A rejected move leaves `position()` unchanged. Replaying the moves from scratch yields the same positions. Undo restores every earlier position, then returns `None` |
| `record_play_keeps_invariants_and_undo_restores_every_position` | The same in `Record` mode with random colors, so out-of-turn moves, ko and superko violations, and single-stone suicide are applied as recorded |
| `parse_of_write_is_the_same_tree` | Random trees of up to 40 nodes with random identifiers and raw values covering every escape: `parse_text(tree.to_sgf())` returns one equal tree, no warnings, and the same text when written again |
| `any_input_parses_extracts_and_replays_without_panicking` | Random bytes, mostly SGF syntax: parse, the writer round trip on every parsed tree, extraction and replay never panic |

To check that the properties can fail, two bugs were planted temporarily in
`game.rs` and reverted. Dropping the hash update for captured stones failed
both play properties. Making positional superko always pass failed the
strict property with "superko allowed a repeated position". Both failures
shrank to a minimal input.

- `decode`: no panic. Valid UTF-8 decoded as UTF-8 without warnings equals

## Changed expectations

These prototype tests now expect a different outcome. Each change is
deliberate, and a test covers it.

Rules (`tests/game_rules.rs`, `src/rules.rs`):

- Moves after two passes are accepted. The core counts consecutive passes;
  whether the game is over is a product-layer decision.
- Komi given as a boolean or a string cannot be represented, because `Komi::new`
  takes `f64`. Those prototype cases are dropped, and the numeric boundary
  cases are kept.
- Setup stones and a first player other than Black are supported
  (`Game::with_setup`).

SGF structure (`tests/sgf_parse.rs`):

- Junk before or after the tree is accepted with `junk_outside_tree` (prototype:
  error).
- Two games in one file are returned as a collection (prototype: error).
- An unclosed tree is accepted with `unclosed_tree` (prototype: error).
- FF[3] lowercase-prefixed identifiers are accepted with `lowercase_identifier`.
- Multiple values, duplicate properties and two moves in one node now parse as
  trees. They remain errors at extraction (`multi_valued_property`,
  `duplicate_property`, `two_moves_in_node`).

Game extraction (`tests/sgf_extract.rs`):

- These are read where the prototype raised an error: `SZ[13]`, `SZ[19:19]`,
  `RU[AGA]`, `FF[3]`, `CA[GBK]`, `KO[]`, and a record with no moves.
- `B[tt]` is read as a pass on boards up to 19×19, with `tt_pass`.
- `AB`/`AW`/`AE` setup, `PL`, and White moving first are supported. If `HA` is 2
  or more and does not match the setup, the result is `handicap_mismatch`.
- `KM` outside the root is read, with `game_info_outside_root`.
- Invalid `KM` (`NaN`, `Infinity`, `0.25`, `151`) gives `komi = None` with
  `invalid_komi` instead of rejecting the file. Komi then has to be
  confirmed, as G04 requires.
- Two Black moves in a row are replayed as recorded, with an `out_of_turn`
  warning (prototype: error).
- Missing `FF`/`GM` give `missing_ff`/`missing_gm` warnings.

## Deviations from ARCHITECTURE (now updated)

- `score` takes `(&Board, Captures, &LifeAndDeath, &Terms)` rather than
  `(&Position, &LifeAndDeath, &Rules)`, so that scoring does not depend on the
  game layer. `Game::score(&marks)` is the convenience form.
- There is no `Game::from_sgf`. Parsing, extraction and replay are separate
  steps, so that rules and komi can be confirmed between them.
- There is no separate lexer: the parser reads the text in one iterative pass.
- Rules live in `board.rs`, `rules.rs` and `game.rs` rather than a `rules/`
  directory.
- `TaxRule::All` is reported as `unsupported_rule` by the scorer instead of
  being approximated.

## Known items

- **No genuine GBK export yet.** `kejie-2025-11-27-gbk.sgf` was derived from
  the UTF-8 file (see `PROVENANCE.md`). A genuine, publishable GBK export from
  a Chinese server should join the corpus when one is available.
- **Ke Jie file source unknown.** Its upstream source was not recorded by the
  prototype. The owner approved publishing it on 2026-11-03.
- **Floating nightly for fuzzing.** The fuzz crate uses the current nightly,
  not a dated one. The version used for the runs above is recorded here.
- **Benchmarks use one machine.** There is no CI benchmark job. Runs on other
  hardware are not comparable with these numbers.
- **Prototype fixtures not yet copied.** MIGRATION D04 (synthetic samples)
  and D07 (`m4-*.sgf` fixtures) are still planned. They join `testdata/sgf/`
  when a later milestone needs them.
- **CI `game` fuzzing is shallow.** The 30 s CI run starts from the SGF
  seeds (1566 to 8008 bytes), which `game` reads as about 780 to 4000 moves
  each, so it manages only about 4000 runs ([below](#ci)). A local 30 s run
  from the same seeds gave
  13,623 runs (439 per second), so the input size, not the runner, is the
  cause. The 600 s local run above is the real evidence for this target.
