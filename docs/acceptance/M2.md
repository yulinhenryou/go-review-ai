## End-to-end tests

Run against the production build served by `vite preview`:

```bash
cd web
npx playwright install --only-shell chromium
npm run build && npm run e2e
```

| Flow | What it checks |
| --- | --- |
| Places stones, captures and undoes | Black captures a corner stone; capture count; clicking an occupied point is rejected with its message; undo restores the captured stone and the count |
| Rejects an immediate ko recapture | 9×9, Japanese rules, the ko from `games.json`: the ko-ban mark appears, the recapture is rejected with `ko_violation` and the board and move number are unchanged |
| Rejects suicide, passes and undoes | Suicide is rejected with `suicide`; two passes show "Both players passed."; five undos return to an empty board and disable Undo |
| Opens a GBK SGF file and steps through it | `testdata/sgf/kejie-2025-11-27-gbk.sgf` is decoded as `gb18030` with the player name 柯洁; replay of 111 moves; Next, End, ArrowLeft and First move |

Each flow records every request made after the page has loaded and expects
none, so the rule decisions are made by the WASM core in the page. To check
that the recorder works, a temporary test started recording before loading
the page: it recorded the HTML, JavaScript, CSS and `.wasm` requests. The
mobile project taps instead of clicking (`hasTouch` is true), so the touch
path runs too. The capture flow and the SGF flow, one per view, also check
that the page has no horizontal scroll.

## Measurements

### WASM size

Built by `npm run wasm` in `web/` (`cargo build` with the `wasm-release`
profile, then `wasm-bindgen --target web`). Sizes are of
`weiqi_wasm_bg.wasm`; gzip uses `-n` so that no file name or time stamp
enters the header (`gzip -9 -n -c < file | wc -c`):

| Profile | Raw bytes | gzip -9 bytes |
| --- | --- | --- |
| `release` (no LTO, `opt-level = 3`) | 450,468 | 252,255 |
| LTO, one codegen unit, `opt-level = 3` | 431,619 | 248,703 |
| LTO, one codegen unit, `opt-level = "s"` (`wasm-release`, chosen) | 401,830 | 242,609 |
| LTO, one codegen unit, `opt-level = "z"` | 405,258 | 241,829 |

The variants were built with `CARGO_PROFILE_WASM_RELEASE_OPT_LEVEL` overrides
into separate target directories. The `wasm-release` output is byte-identical
to the module in `web/src/wasm/` (`cmp`). `"s"` is 3,428 bytes smaller raw
than `"z"` and 780 bytes larger gzipped. The CI `web` job prints both sizes
on every run. Vite reports the built asset as 401.83 kB, 243.64 kB gzip
(its own gzip settings).

### Python wheel build time

`uv build --wheel` in `crates/weiqi-py` (maturin, release profile), with
`--config-setting=build-args="--target-dir <empty directory>"` for the cold
build. Crate sources were already downloaded, and uv had maturin cached:

| Build | Wall time | CPU (user + sys) |
| --- | --- | --- |
| Cold (empty target directory) | 7.70 s | 21.11 s |
| Warm (same target directory, no changes) | 0.88 s | 0.38 s |

Output: `weiqi_core-0.0.0-cp314-abi3-macosx_11_0_arm64.whl`, 527,855 bytes.

## Decisions

- ADR-P15 (Python binding shape) and ADR-P16 (WASM binding shape) stay
  *Proposed* until the owner approves M2.
- TanStack Query is not chosen in M2: the shell makes no server call, so the
  choice moves to the milestone with the first API call (ARCHITECTURE §11).
- Playwright with Chromium only; locally only the headless shell is
  installed, so tests run headless.

## Known items

- Scoring is not exposed through either binding yet, and the WASM binding has
  no legal-move mask.
- The board has no coordinate labels and cannot be played from the keyboard
  (ARCHITECTURE §11, M4).
- `npm audit` reports a moderate advisory (GHSA-g3hv-75wg-m249) in
  `minimatch`, pulled in by eslint and typescript-eslint, development only.
  The offered fix downgrades eslint to 9.x and was not applied.
- The GBK SGF is derived from a UTF-8 file, not a genuine server export
  (as in M1).
